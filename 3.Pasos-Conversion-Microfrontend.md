# Documentación: Conversión a Microfrontends con Angular (Standalone)

Esta guía documenta los pasos realizados para convertir los proyectos `web-home`, `web-apuestas` y `web-recargas` a una arquitectura de Microfrontends utilizando Module Federation, adaptado para proyectos Angular Standalone.

## 1. Instalación de Dependencias

Se instaló la librería `@angular-architects/module-federation` en cada proyecto:

```bash
npm install @angular-architects/module-federation --save-dev
```

## 2. Inicialización de Module Federation

Se ejecutó el esquemático de inicialización para cada proyecto, asignando los puertos correspondientes:

*   **web-home**: Puerto 4201
*   **web-apuestas**: Puerto 4202
*   **web-recargas**: Puerto 4203

```bash
ng g @angular-architects/module-federation:init --project web-home --port 4201 --type host
ng g @angular-architects/module-federation:init --project web-apuestas --port 4202 --type remote
ng g @angular-architects/module-federation:init --project web-recargas --port 4203 --type remote
```

*(Nota: Se seleccionó la configuración "Module Federation with webpack (classic)" durante la inicialización)*

## 3. Adaptación para Standalone Components

Dado que los proyectos utilizan la arquitectura Standalone (sin `AppModule`), se realizaron las siguientes adaptaciones:

### Remotes (`web-apuestas`, `web-recargas`)

1.  **Exposición de Rutas**: En lugar de exponer un `Module`, se expuso el archivo de rutas `app.routes.ts`.
2.  **Configuración de Rutas**: Se aseguró que `app.routes.ts` definiera una ruta por defecto hacia el componente principal (`App`).

**web-apuestas/webpack.config.js**:
```javascript
exposes: {
  './Routes': './src/app/app.routes.ts',
},
```

### Shell (`web-home`)

1.  **Consumo de Rutas**: Se configuró `app.routes.ts` para cargar los remotes utilizando `loadRemoteModule` y acceder a la propiedad `routes` expuesta.

**web-home/src/app/app.routes.ts**:
```typescript
loadChildren: () =>
  loadRemoteModule({
    type: 'module',
    remoteEntry: '...',
    exposedModule: './Routes',
  }).then(m => m.routes),
```

## 4. Configuración de Webpack

Se ajustó el archivo `webpack.config.js` en todos los proyectos para definir `publicPath` y `uniqueName` correctamente, evitando errores de validación de esquema.

```javascript
const config = withModuleFederationPlugin({ ... });
config.output.publicPath = ...;
config.output.uniqueName = ...;
module.exports = config;
```

## 5. Configuración de Entornos

En `web-home`, se crearon los archivos de entorno para manejar las URLs de los remotes dinámicamente:

*   `src/environments/environment.ts`
*   `src/environments/environment.prod.ts`

## 6. Verificación

Se ejecutó `ng build` en todos los proyectos para validar que la configuración de Webpack y TypeScript es correcta.

---

### Cómo ejecutar

1.  Iniciar cada proyecto en terminales separadas:
    ```bash
    npm start -- --project web-home
    npm start -- --project web-apuestas
    npm start -- --project web-recargas
    ```
2.  Acceder al Shell en `http://localhost:4201`.
